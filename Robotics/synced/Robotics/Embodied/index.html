1. Embodied Intelligence(具身智能)

机器人学主要依赖于数学、物理、机械工程、电子工程、计算机科学，还涉及哲学、心理学、生物学等领域。

机器人的核心是运动—受控制的编程运动。

机器人学研究的是怎样综合运用机械装置、传感器、启动器和计算机来实现人类某些方面的功能。

4.1. 大小脑一体化

运动控制（motion control）是由控制器、驱动器、电机和传感器组成的整套硬件和软件系统，用来协调机器人的关节运动。

  • 大脑（大脑皮层）： 负责思考、决策、感知环境（如识别物体、规划路径）。
  • 小脑（运控系统）： 负责协调肢体、保持平衡、执行精细动作（如走路不摔倒、抓取物体）。

传统的做法，是让大脑和小脑各干各的。大脑想好了，输出一条指令；小脑接到指令，执行动作。是【先想后做】—我想好了所有
步骤，然后一步步执行。
新的方式：【边做变想】—我一边执行，一边根据反馈调整计划。

把机器人大小脑融合起来，一起协同工作。上层的决策可以直接影响底层的动作，底层的感知可以即时反馈给上层，中间的技能层负
责把两边对齐。让大脑真正「感知」到身体在做什么、环境发生了什么变化；也让身体知道大脑想要什么，并且能够灵活调整去
实现它。实现理解任务、感知环境、调整决策、组合技能、物理执行的完整闭环。

  1. 具备自主感知、理解、决策、行动的能力。让机器人能够同时想、同时动、边思考边干活儿。
  2. 指令的决策：把新指令纳入规划，与人交互后，通过调整优先级去实现。
  3. 机器人的决策不是一次性的规划，而是与环境持续的交互、反馈和响应的过程。

预设的动作库：走路、抬手、挥手、转身、踏步。

5. Structure Design(结构设计)

机器人结构设计包括机械结构设计和电子电路设计两大部分。

机械结构设计主要涉及机器人的外形设计、关节布局、连杆长度等方面，以确保机器人具备良好的运动性能和稳定性。电子电路设计则
包括传感器布置、电机驱动电路、控制系统等，以实现对机器人的精确控制和反馈。

5.1. 灵巧手

灵巧手：电机 + 减速器（谐波减速器、行星减速器）

  • 谐波减速器：精准省空间、适合手指。
  • 行星减速器：便宜、适合手掌。

6. Joint Module(关节模组)

机器人关节模组是机器人系统中的关键组成部分，负责实现机器人的运动和姿态调整。

机器人的关节由驱动器驱动，关节提供自由度，允许相对运动。

构成关节模块的主要部件有：

  • 电机
  • 减速器：主要目的是提高电机的输出力矩，提高电机的位置控制精度。
  • 编码器：为电机的位置、速度等基本信息提供反馈。
  • 抱闸：实现断电自锁。
  • 驱动器

机器人一般有多个关节且需要高频率的控制，所以通信协议一般用 CAN 总线或者 EtherCAT 总线来进行通信控制。

  • CAN 总线的最高波特率为 1Mbps
  • EherCAT 总线 波特率最高可以达到 100M bps

7. Kinematics(运动学)

运动学研究机器人的几何结构和运动特性，而不考虑引起这种运动的力。主要研究如何描述和计算机器人各个连杆的位置、姿态、速度
和加速度。

7.1. Concept(概念)

7.1.1. Rigid body

7.1.1.1. 什么是刚体（Rigid Body）

在机器人系统中，刚体指的是一个理想化的物理模型：这个物体上任意两点之间的距离，无论物体如何运动（平移、旋转），永远保持不变——也就是说，物体本身不会发生形变、拉伸、弯曲或扭曲。

用数学语言说：如果一个物体是刚体，那么描述它在空间中的状态，只需要 6 个自由度（DOF） 就够了：

  • 3个平移自由度：x, y, z（位置在哪）
  • 3个旋转自由度：roll, pitch, yaw（朝向是什么，通常用四元数或旋转矩阵表示）

这正是为什么一个 TF 坐标系（一个 TransformStamped）只需要一个平移向量 + 一个旋转四元数就能完整描述——因为它默认描述的就是一个刚体的位姿（pose）。

7.1.1.2. 为什么要用”刚体”这个假设

现实中没有任何物体是100%绝对不变形的（哪怕是钢铁，受力也会有微小形变），但刚体是一种简化建模的手段：

  1. 大幅降低计算复杂度：如果考虑形变，描述一个物体的状态可能需要无穷多个自由度（物体上每一点都可能独立移动）；假设是刚体，一个物体永远只用6个数就能完整描述它在空间中的状态
  2. 绝大多数工程场景下形变可以忽略：机器人的底盘、连杆、外壳，在正常工作条件下形变量极小，不影响任务精度，简化为刚体带来的误差可以接受

7.1.1.3. 刚体在机器人系统中具体用来做什么

1. 描述机器人的每一个部件（link）

一个机器人由多个刚体通过关节（joint）连接组成——这也是为什么 URDF（机器人描述文件）里，每个 <link> 标签本质上就是在定义一个刚体（它的形状、质量、惯性矩阵），而 <joint> 定义的是刚体之间如何相对运动（旋转关节、移动关节等）。

2. 支撑正/逆运动学计算

正是因为每个连杆都是刚体（内部点与点距离不变），才能用固定的齐次变换矩阵去描述相邻连杆之间的相对位姿关系，进而通过连乘得到末端执行器相对基座的位姿——这就是正运动学；反过来求解关节角度就是逆运动学。如果连杆会形变，这套数学框架就完全不成立了。

3. TF 树里的每一个 frame，本质代表一个刚体（或刚体上固定的一个点）

base_link、camera_link、lidar_link——每一个都假设是”焊死”在对应部件上的刚体坐标系，部件动，坐标系跟着动；部件不动，坐标系不动；部件内部结构不会因为运动而扭曲变化。

4. 支撑动力学仿真与控制

在物理仿真（Gazebo、PyBullet等）和动力学控制算法（比如力矩控制、阻抗控制）里，刚体动力学方程（牛顿-欧拉方程、拉格朗日方程）都建立在”刚体”假设之上，用质量 + 惯性张量就能完整描述一个物体对力/力矩的响应，不用管它内部每个质点具体怎么运动。

5. 碰撞检测、抓取规划

机器人抓取物体、路径规划中的碰撞检测，通常也把被抓取的物体、机器人的每个连杆当作刚体处理，用固定的几何形状（网格、包围盒等）去判断是否碰撞，因为刚体的几何形状在运动过程中不会变化，大大简化了检测算法。

7.1.1.4. 什么时候”刚体”假设会失效、需要用别的模型

场景 说明
软体机器人（soft robotics） 材料本身会大幅形变（比如硅胶手指、气动软体抓手），完全不能用刚体模型
柔性连杆机械臂 长悬臂在高速运动或负载下会有明显弹性形变，需要考虑柔性动力学
绳索、电缆、软管 形状随时变化，通常用多段刚体近似（离散化成很多小刚体串联）或专门的柔性体仿真
布料、液体、可变形物体抓取 完全无法用单一刚体描述，需要用有限元、粒子系统等方法建模

一句话总结：刚体是机器人建模的基础假设——把一个物理部件简化为”只会整体平移和旋转、内部结构永不改变”的理想物体，这样才能用简洁的6自由度位姿（平移+旋转）去描述它，支撑起运动学、动力学、TF、碰撞检测等整套机器人系统的数学基础。

7.1.2. Configuration

在机器人学中，Configuration（构型/位形） 是一个最基础且严格定义的数学概念。它指的是：完整描述机器人系统中每一个点的位置所需的最小一组独立参数。

简单来说，Configuration 回答了这样一个问题：“在这一瞬间，机器人的所有部件确切地在哪里？”

  • 符号表示：通常用向量 qq 表示。
  • 构型空间：所有可能的 configuration 组成的集合称为 *C-space (Configuration Space)*。如果机器人有 nn* 个自由度，则 q∈Rnq∈Rn* （或流形）。
  • 关键点：Configuration 只关心“位置/姿态”，不包含速度、加速度或受力信息。那些属于“状态”的范畴。

Configuration vs. State 的对比

概念 包含内容 维度 用途
Configuration ( q) 仅位置/关节角 n(自由度) 描述几何形态、碰撞检测、运动学
State ( x) 位置 + 速度 (+ 其他) >=2n 动力学建模、控制、滤波

7.1.3. task space(任务空间)

任务空间是指机器人末端执行器在三维空间中可以达到的位置和姿态的集合。任务空间通常使用笛卡尔坐标系来描述，包括位置（X、Y
、Z坐标）和姿态（滚转(roll)、俯仰(pitch)、偏航角度(yaw)）。任务空间反映了机器人在执行特定任务时所需的操作范围和能力。

机器人位形空间(configuration space)与任务空间(task space)之间并非——映射的关系。机器人的工作空间（workspace）则可以定义
为末端执行器所能达到的任务空间的子集。

7.1.4. frame(坐标系)

在机器人学（特别是 ROS/ROS 2 的 TF 库）中，使用 “Frame” 而不是 “Coordinate”、”System” 或 “Point” 等词汇，主要源于刚体运动学（Rigid Body Kinematics）的历史惯例和物理语义的精确性。

  • Frame = Reference Frame（参考系/参照架）： 在物理学和力学中，“Frame”特指一个与某个具体物体固连（Attached） 的坐标系。它不仅仅是一组数学上的 XYZ 轴，还代表了该物体的姿态（Pose）和位置。当物体移动时，这个 Frame 也随之移动。
  • Coordinate System 过于抽象： “Coordinate System”通常指代纯粹的数学定义（如笛卡尔坐标系、极坐标系），它不一定依附于某个实体。而在 TF 中，我们关心的是“激光雷达的坐标系”、“底盘的坐标系”，它们是实体的属性，因此用 Frame 更准确。

ROS 社区和 REP（ROS Enhancement Proposal，尤其是 REP-105）给出了一套推荐的坐标系命名与层级规范：

7.1.4.1. world frame

  • 世界坐标系是整个机器人系统里固定不变、独一无二的全局参考系，所有其他坐标系（机器人本体、传感器、地图上的物体等）最终都可以追溯到它，用来回答”东西在绝对空间里的什么位置”这个问题。

  • 它本身不依附于任何运动的物体，也不随时间改变原点或朝向；

  • world（或 map）frame 本身的原点位置没有绝对物理意义，是人为定义的：

    • 仿真里，通常是仿真启动时的默认原点（比如 Gazebo 世界文件里的 (0,0,0)）

    • 真实机器人上，如果用 SLAM 建图，通常是机器人开机、算法启动的那一刻所在的位置被定义为 map 的原点（”我从这里开始建图，这里就是(0,0,0)”）；即原点 (0,0,0) = 机器人刚启动时 base_link 所在的位置；朝向：以初始状态的人形机器人正下方的点为原点，规定机器人当前朝向的正前方为 X 轴正方向，左方为 y 轴，垂直向上为 z轴，构成右手坐标系。

    • 如果有真实的全局坐标（比如 GPS/RTK），有时会对齐到某个大地坐标系的参考点；

  • world frame 是整个系统里”钉死不动”的绝对参考原点，其他所有坐标系的位置最终都相对它来描述；它的具体原点在哪，由你的建图/定位系统或者仿真环境在启动时人为约定。

7.1.4.2. base link

  • 是 ROS/ROS2 官方 REP-105 里明确规定的固定名字，专指”机器人本体的参考坐标系”。它是一个具体的、标准化的坐标系名字，几乎所有 ROS 机器人包(nav2，robot_state_publisher，URDF等)都默认认这个名字；
  • 原点通常固定在机器人的几何中心或旋转中心；
  • 会随着机器人移动而移动——机器人往前走，base_link 在 world 下的位置就跟着变；
  • 是机器人上其他部件（雷达、相机、机械臂基座等）坐标系的参考基准；
  • world 到 base_link 的变换（TransformStamped）,本质上就是在回答：**”机器人现在在世界坐标系里的哪个位置、朝向是什么？”**

7.1.4.3. laser link

雷达坐标是雷达所在的位置。

7.1.4.4. odom frame

  • 机器人要移动，里程计会累积位置，这个位置的参考系叫做**里程计坐标系(odom)**；
  • 保证连续、局部平滑（不会突然跳），但长期会有累积漂移误差（走得越久，误差越大）；
  • 数据来源：轮式里程计 / IMU 融合；

7.1.4.5. map frame

  • 里程计数有累积误差和漂移，绝对位置的参考系叫做地图坐标系（map）；
  • 保证全局准确（靠传感器匹配环境地图纠正误差），但纠正的瞬间坐标值可能突然”跳一下”；
  • 数据来源：SLAM / 定位算法（如 AMCL，SLAM Toolbox）；

7.1.4.6. tool frame

工具坐标系安装在机器人末端执行器上的局部坐标系，用于描述末端执行器相对于自身的位姿。比如：末端的夹爪坐标。

7.1.4.7. Object frame

  • 工件坐标系是机械加工、机器人操作领域里非常常用的一个概念，指的是以被加工/被操作的工件本身为参考原点建立的坐标系，而不是以机床、机器人底座或世界原点为参考。

  • 工件坐标系的参考对象：被加工/被操作的工件本身；

7.1.4.8. absolute frame

绝对坐标系通常指机器人系统中某个固定的参考坐标系，一般用于描述机器人在环境中的位置和姿态。

7.1.4.9. relative frame

相对坐标系通常指相对于某个参考坐标系的坐标系，用于描述机器人各部分之间的位置关系。

7.1.5. End Effector(末端执行器)

末端执行器是机器人系统中与环境直接交互的部分，通常安装在机器人机械臂的末端。它可以是各种类型的工具或装置，如机械手、夹具、焊接工具、喷涂设备等。末端执行器的设计和功能取决于机器人的应用需求，旨在完成特定的任务，如抓取、操作、加工等。

7.1.6. Cartesian Space(笛卡尔空间)

笛卡尔空间是指使用笛卡尔坐标系（Cartesian Coordinate System）来描述物体位置和运动的空间。在机器人学中，笛卡尔空间通常用于表示机器人末端执行器的位置和姿态。

笛卡尔坐标系由三个互相垂直的轴（通常称为 X、Y、Z 轴）组成，用于描述三维空间中的点，笛卡尔坐标系又称直角坐标系。

7.1.7. Jacobian Matrix(雅可比矩阵)

雅可比矩阵是描述机器人关节速度与末端执行器线速度和角速度之间关系的矩阵。它在机器人运动学中起着关键作用，用于将关节空间
的速度映射到任务空间的速度。雅可比矩阵的每一列对应一个关节变量对末端执行器位置和姿态的影响。

7.1.8. pose(位姿)

位姿(position and orientation) 是描述物体在空间中位置和姿态的组合。

位置通常用三维坐标（X、Y、Z）表示，而姿态则描述物体相对于参考坐标系的方向，通常使用欧拉角、四元数或旋转矩阵来表示。

姿态的三种常用表示方法：

  1. X-Y-Z 固定角
  2. Z-Y-X 欧拉角
  3. Z-Y-Z 欧拉角

7.1.9. link

在机器人学中，Link（连杆/链接） 是指机器人机械结构中连接两个相邻关节的刚性或柔性实体构件。它是构成机器人运动链的基本物理单元。

简单来说：如果把关节比作“轴”或“铰链”，那么 Link 就是被这些轴连接起来的“杆”或“臂”。

  • 物理本质：一个具有质量、惯量和几何形状的刚体（在大多数基础模型中假设为刚体）。
  • 功能：传递运动和力/力矩，维持关节之间的固定空间关系。
  • 编号惯例：通常从基座开始编号，Base 为 Link 0，末端执行器所在的最后一个连杆为 Link nn 。对于 nn 个关节的串联机器人，通常有 n+1n+1 个 links（含基座）。

特殊类型的 Link

  • Base Link：机器人的固定基座，通常作为整个坐标系的根节点。
  • End-Effector Link：末端连杆，工具/夹持器安装于此，其坐标系即工具坐标系。
  • Virtual / Dummy Link：没有实际物理质量，仅用于定义坐标系或简化运动学建模的辅助连杆。
  • Flexible Link：在柔性机器人中，Link 不再是刚体，需考虑弹性变形（如太空机械臂、软体机器人）。

7.2. Forward Kinematics(正向运动学)

如何根据机器人的关节角度，描述每个连杆的位置和姿态，被称为正向运动学。

正运动学研究物体的运动，而不考虑引起这种运动的力。正运动学是一个计算末端执行器位置和姿态的静态几何问题，基于已知的关节
参数（如关节角度或位移），通过一系列的几何变换来确定末端执行器在空间中的位置和方向。

具体来讲，给定一组关节变量（如关节角度或位移），正向运动学通过以下步骤计算末端执行器的位置和姿态：

  1. 定义坐标系：为每个连杆和关节定义局部坐标系，通常使用
    Denavit-Hartenberg（D-H）参数法来系统地描述这些坐标系之间的关系。
  2. 建立变换矩阵：使用齐次变换矩阵来表示
  3. 连杆之间的几何关系。这些矩阵包括旋转和平移信息。
  4. 连乘变换矩阵：通过将各个连杆的变换矩阵相乘，得到从基坐标系到末端执行器坐标系的总变换矩阵。
  5. 提取位置和姿态：从总变换矩阵中提取末端执行器的位置信息（通常是矩阵的前三列）和姿态信息（通常是旋转矩阵或欧拉角
    ）。

正向运动学中研究的内容

  • 位置
  • 速度
  • 加速度
  • 位置变量对于时间或者其他变量的高阶微分。

7.3. Inverse Kinematics(逆向运动学)

逆运动学研究的是机器人为什么要这么运动？涉及力。即根据每个连杆的位置和姿态，计算所有可到达的机器人关节角度。

正运动学方程是各个关节变量的函数，描述了工具坐标系相对于基坐标系的位置和姿态。
给定工具坐标系的位置和姿态，通过逆运动学方程可以计算出各个关节变量的值。

8. Dynamics(动力学)

动力学是研究物体运动及其原因的科学，主要关注力和力矩如何影响物体的运动状态。在机器人学中，动力学涉及分析机器人在外部力
作用下的运动行为，包括加速度、速度和位置的变化。

8.1. Forward Dynamics(正向动力学)

正向动力学研究的是给定机器人各个关节的力和力矩，计算机器人各个连杆的加速度、速度和位置变化。

正向动力学方程描述了机器人各个连杆的加速度、速度和位置变化，作为各个关节力和力矩的函数。给定各个关节的力和力矩，通过正
向动力学方程可以计算出机器人各个连杆的运动状态。

8.2. Feedback Control(反馈控制)

人形机器人的步态模式要能防止机器人自身在没有干扰的情况下翻到，一般是通过反馈控制来稳定的。

9. Control Synthesis(控制综合)

机器人控制器的工作就是将任务指令转换成驱动关节的力和力矩。

10. ZPM

Zero Moment Point（零力矩点）：指机器人脚底从地面承受的力矩为 0 的点，总是在地面和脚底接触面的某个地方。

11. Visual Perception(视觉感知)

视觉感知是机器人通过摄像头等视觉传感器获取环境信息，并进行处理和理解的过程。视觉感知在机器人导航、物体识别、环境建模等
方面起着关键作用。

11.1. Odometry(里程计)

里程计（Odometry） 是机器人估计自身位置和姿态（位姿）随时间变化的方法。简单说，就是”机器人知道自己走了多远、转了多少角度”的技术。

这个词来自”odometer”（汽车里程表），原理也类似：通过测量运动相关的量，累积计算出当前相对于起点的位置。

里程计组成部分

  • 车轮编码器（Wheel Encoder）
  • 运动模型（Motion Model）
  • 传感器融合（Sensor Fusion）
  • 运动估计和滤波算法（Motion Estimation and Filtering Algorithms）

核心原理：

里程计通常通过积分运动信息来实现：

  • 测量一小段时间内的位移/转动增量
  • 把这些增量不断累加，得到从起点到现在的总位移

根据使用的传感器不同，里程计主要分为以下几类：

类型 传感器 优点 缺点 原理 常用应用
轮式里程计 轮编码器 简单、低成本、高频 轮子打滑、磨损会导致累积误差 编码器测量车轮转数，结合轮径、轮距算出位移和旋转 轮式机器人、扫地机器人
惯性里程计 IMU (陀螺仪+加速度计) 不受外部环境干扰、响应快 零偏漂移严重，误差随时间发散 加速度计+陀螺仪积分得到速度和位置 几乎所有移动机器人（常与其他方式融合）
视觉里程计 (VO) 相机 信息丰富、无机械磨损 受光照/纹理影响大，计算量大 分析连续摄像头图像中特征点的变化，推算相机运动 无人机、自动驾驶
激光/雷达里程计 LiDAR 精度高、抗光照干扰 成本高、在特征缺失环境易失效 匹配连续激光扫描帧来推算运动 高精度导航、SLAM
多源融合里程计 VIO / LIO / Wheel-IMU 互补优势、鲁棒性强 算法复杂、标定要求高

用来干什么

  1. 自身定位：机器人不知道”我在哪”就没法规划路径、避障、返回目标点
  2. 闭环控制的反馈：比如让机器人直线走1米、转90度，需要里程计告诉它”已经走了多少”
  3. SLAM 的基础：同步定位与地图构建（SLAM）通常把里程计作为”预测”环节，再用传感器观测（如激光、视觉）来修正累积误差
  4. 步态控制反馈（对四足机器人尤其重要）：估计机身速度和姿态，用于步态调整、平衡控制

累积误差（Drift）

里程计最大的缺陷是误差会累积——每次测量都有一点点误差，走的时间越长、距离越远，误差累积得越大，最终估计位置会”漂移”，偏离真实位置。

所以实际系统很少单独用里程计做长期定位，常见做法是：

  • 多传感器融合：轮式/腿式里程计 + IMU + 视觉，用卡尔曼滤波（EKF）或因子图优化融合
  • 配合绝对定位手段修正：比如 GPS（室外）、激光/视觉SLAM 回环检测、UWB 定位等来周期性”纠偏”

里程计的优点是实现简单、成本低廉，但其精度会受到轮子打滑、地面不平等因素的影响，容易产生累积误差。因此，里程计常常与其他传感器（如 IMU、激光雷达等）结合使用，以提高定位精度和鲁棒性。

11.2. IMU

惯性测量单元（Inertial Measurement Unit, IMU）是一种用于测量物体加速度和角速度的传感器，通常由加速度计和陀螺仪组成。

IMU可以提供物体在三维空间中的运动信息，广泛应用于机器人、无人机、汽车导航等领域。

  • 加速度计：用于测量物体在各个轴向的线性加速度，通常采用微机电系统（MEMS）技术制造。加速度计可以检测物体的加速和减速，
    从而推算出物体的位置变化。
  • 陀螺仪：用于测量物体的角速度和旋转速度，从而推算出物体的姿态变化，通常也采用 MEMS 技术制造。
